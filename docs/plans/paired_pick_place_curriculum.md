# 双层柜取放：成对布局课程执行计划

状态：待实施。本计划不代表实验已获授权或验证已完成。

范围：在无门双层柜中从上层抓杯、放到下层，同时保留周围物体。先使用一个杯子和一个可移动的碗，完成双物体实验后再增加物体。保留现有单杯基线和[柜内覆盖调查](cabinet_coverage.md)。

研究问题：在模拟器控制步数和世界模型（WM）更新次数相同的条件下，使用历史预测误差选择布局编辑，是否比随机编辑更能改善共享 GNN 在未见过的「取物位置 × 放置目标 × 周围物体摆放」组合上的预测？保留 MAC 的误差条件化编辑器、学习进展（learning progress）和新颖度（novelty）。不手工标注哪个 cell「靠近」「挡路」或「无关」：由几何检查确定合法摆放，由实际执行结果提供反馈。

## 1. 确定物理执行和观测协议

- [ ] 从[无门双动作配置](../../configs/raps_gnn_actor_cabinet_pick_place_grid_compact.yaml)和[规划式取放执行器](../../domain/robocasa/pick_place.py)出发，在[回合初始化](../../domain/wall_cabinet_env.py)加入按物体指定摆放位置的输入，仅在 reset 时应用。抓取、放置的**动作目标坐标**与**物体初始摆放候选**分开。根据层板支撑几何和物体碰撞边界自动生成候选，由支撑面决定高度，检查支撑、越界和初始重叠。各组保持物体几何和朝向、柜体几何、机器人根坐标系、100 Hz 仿真／20 Hz 控制及执行器配置一致。初始摆放合法但执行中挡路，仍是有价值的结果。
- [ ] 确认双动作流程从 grasp 到 place 保留实际夹持状态，不在中间重置，也不执行抓取专用流程的回默认位。核对 WM 能看到哪些抓取／放置输入、夹持物体身份、绑定状态和在手物体位姿。若缺少必要信息，在采集前补齐最少的可观测字段，并为状态协议标记新版本。明确 WM 的动作和预测目标含义。现有单杯 replay 和 checkpoint 不用于初始化这次双物体实验。
- [ ] **验收**：碗在任一层时都能稳定初始化；关闭新功能后基线 reset 行为不变；在覆盖多个上层取物点和多个下层目标的小规模用例中，实际完成取、搬、释放和撤离。记录柜体碰撞、规划拒绝、释放稳定性及实际物体位姿。已有的单个完整成功案例可作为起点，不能据此判定下层目标全部可用。分别验证初始摆放是否合法、带物路径是否可行；物理覆盖不足时，先解决这一点再训练编辑器。

## 2. 采集成对布局并计算误差

- [ ] 使用共享的带种子采样器选择取物点、放置目标及基础布局 A。编辑器只移动一个非目标物体得到 B；双物体阶段只移动碗。每对中固定目标杯、预定取放命令和 reset 条件。各组使用同一个独立于 GNN 和编辑器的固定行为策略，共享动作提议的随机种子，但允许规划路径和执行结果不同。只在回合 reset 时应用编辑；独立于编辑器随机决定 A/B 执行顺序，使用重建的场景和重复种子估计仿真波动。
- [ ] 复用[技能采集器和端点导出](../../exploration/raps/raps_gnn_actor.py)。记录配对 ID、实验组、种子、任务、指定和实际初始位姿、实际宏动作的输入／动作／输出、执行状态、训练资格、各物体运动、模型版本和控制步数。沿用训练样本资格规则，单独记录零控制步的拒绝和被截断的轨迹尾段。未执行 place 就不生成虚假的放置端点；放置误差仅在实际执行过的样本上评分，并单独报告执行次数和端到端完成率。如果抓取门槛导致放置样本不足，增设单独计预算的 place 探测，用明确的方法在物理仿真中建立可匹配的夹持状态。
- [ ] 建立与训练 replay 分离的独立课程评分对。按阶段和物体计算绝对端点误差，以及**成对效应误差**：分别用 A/B 各自真实的宏动作前状态计算位移，再对「预测位移差 B−A」与「实际位移差 B−A」之差取范数。只对结果可比较的样本计算成对效应。报告杯和碗的 XYZ 误差（mm）、各阶段计数、失败类别和未执行次数。连续状态的点预测不能直接当作校准过的成功概率。组间比较前固定物理尺度和按阶段／物体汇总的规则。分批用当前 WM 刷新缓存的历史预测，或者明确记录模型版本和记录时效，以识别过时误差。
- [ ] **验收**：用重复种子复跑少量布局对，建立 A/A 重复执行的波动基线，确认至少一个可测的 A/B 效应或有意义的规划拒绝差异，并覆盖成功和不成功的执行。核对配对条件、精确控制步计数、端点提取，以及已知数值样例上的效应误差计算。

## 3. 接通 WM 与 PPO 训练闭环

- [ ] 所有组从同一份双物体 bootstrap 数据和初始状态出发，使用相同 WM 架构、损失、归一化和固定的优化器更新预算。复用[现有 WM 后端](../../exploration/cee_us/cee_us_backend.py)，将 WM 拟合与机器人 actor 更新分开。按同一版本的采样规则抽取符合条件的新旧训练样本；记录新数据实际被抽到的情况，必要时为所有组设定相同的新旧数据配额。归一化统计只用训练数据拟合。
- [ ] 第一版使用带动作 mask 的小型离散 PPO。输入为当前任务、基础布局位姿及近期成对记录的汇总编码（位姿、动作、各物体预测残差、执行 mask、样本数和记录时效）。输出为被移动物体的合法目标层／cell，排除原地不动。一次决策生成一对布局，并在 WM 更新后得到一次奖励。该设置学习下一次怎样编辑最有用，暂不测试长程课程规划。
- [ ] 每次决策时冻结当前 WM 完成采集；在固定的课程评分对上计算其更新前误差；用采到的布局对和历史训练数据更新 WM；在同一批评分对上计算更新后误差。奖励为**保留正负号的更新前后误差降幅＋有界新颖度**。以物体相对取物点和放置点的位置，与历史生成布局比较，使用固定距离计算新颖度。用开发数据确定后锁定奖励尺度，分别记录两项奖励。更新 PPO 前保持编辑器参数不变，积累在策略（on-policy）决策，保存每次的历史输入快照、动作 mask 和旧动作对数概率。每个训练轮次边界保存 WM 和编辑器参数、各自优化器、归一化统计、档案、数据划分清单、计数器及 RNG 状态。
- [ ] **验收**：用小规模端到端冒烟验证确认：编辑器确实改变 reset 布局；有效转移进入 WM；评分数据无法流入训练；奖励可从保存的预测复算；PPO 更新后参数有限。确认从轮次边界恢复时，给定同样的记录输入，可以复现下一次编辑提议和 replay 抽样。

## 4. 做对照实验并判断泛化

- [ ] 按「布局 × 任务」组合预先划分可训练布局、课程评分布局和封存的最终测试布局；同一对的 A/B 和全部重复回合必须在同一份划分内。先用开发冒烟实验确定样本数量、容差和预算，在正式比较前锁定这些设置和主指标。课程评分数据会影响 PPO，属于开发数据；最终测试数据不得进入 PPO、replay、归一化、权重选择或早停。另保留旧布局评估，用来检查遗忘。
- [ ] 首先比较 PPO 与**均匀随机选择合法编辑**。两组采用同一成对采集流程、固定行为策略、共享 bootstrap、replay 规则和 WM 更新次数。匹配总模拟器控制步数，包括 A/B 两边、维护动作和任何准备动作；另外报告 reset 次数、零控制步的尝试和有效宏动作数。预先规定预算耗尽时怎样处理未完成的布局对。若主对照值得进一步拆解，再分别移除历史输入和新颖度奖励。在重要运行前冻结源码和配置，记录种子、运行环境和产物路径；大规模模拟或训练前确认预算。
- [ ] 报告抓取和放置端点误差（按宏动作汇总）、杯和碗的成对效应误差、尾部误差、覆盖和各阶段执行分母。在相同最终测试对上比较，按布局／回合层级报告成对结果的不确定性；单种子仅视为试验性结果。只有预先锁定的最终指标在留出的组合上改善，且未掩盖旧布局、放置覆盖或任一物体预测的实质退化，才声称泛化能力提升。
- [ ] 完成上述对照后再考虑第二个周围物体，以及严格的「有／无物体」对照。可变物体数量的 WM 应屏蔽缺席节点及其消息、聚合和损失，并明确建立新的 replay／checkpoint 协议。多物体结果与固定双物体实验分开报告。

交接：执行完成后，把最终方法、协议和证据归入长期记录，将已验证的结果追加到工作日志，再移除这份执行清单。附带的 MAC 论文保持只读。
